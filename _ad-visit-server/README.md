# 후성 홈페이지 네이버 광고 방문 기록

이 브랜치에서는 HTML에 추가된 스크립트의 `data-endpoint`가 비어 있어 수집이 꺼져 있습니다. 수집 서버는 GitHub Pages와 별도로 운영합니다.

- 네이버 자동추적 URL에서 광고 ID와 매체 ID가 확인된 방문만 기록합니다. 키워드 ID가 유효하면 함께 저장합니다. 실제 이용자가 입력한 검색어, 전체 URL, 쿠키, 상담 내용은 전송하지 않습니다.
- 서버는 수신 시각(UTC 밀리초), HTTPS 프록시에서 확인한 IP, 광고·매체·키워드 ID, 유입 도메인 분류, 랜딩 경로, 보관기간 내 동일 IP 선행 기록 여부를 저장합니다. 같은 IP는 공유 회선일 수 있습니다. 새로고침이나 복사된 링크도 기록될 수 있으므로 방문 로그와 네이버 과금 자료를 대조해야 합니다.
- 국내 저장을 우선 검토합니다. 사무소가 처리 근거와 최소 보관기간을 확정하고 처리방침에 목적·항목·기간·파기 및 권리행사 방법을 반영한 후 활성화합니다. 정당한 이익을 적용한다면 원본 IP 필요성과 이용자 권리 비교를 문서화합니다. 동의를 근거로 할 경우 사전 선택 동의 UI를 추가한 뒤 활성화합니다. 수탁자나 국외 조회·저장이 있다면 위탁 및 국외이전 요건을 별도로 확인합니다.
- 접속 기록은 7일을 초기 검토안으로 제시합니다. 이 저장소에서 1–14일을 설정할 수 있으며 법정 기준이 아닙니다. 서버 시작과 이후 매분 만료 기록을 삭제합니다. 전용 암호화 볼륨의 비공개 디렉터리에 DB를 두고 서비스 계정과 지정 관리자만 접근하도록 합니다. 방문 IP가 남는 프록시 액세스 로그와 외부 로그 전송을 끄고 DB를 일반 백업에서 제외합니다.

## 배포

1. Node.js 24 서버에서 비공개 경로로 `AD_LOG_DB`, 확정한 일수로 `AD_LOG_DAYS`를 설정하고 `node server.mjs`를 실행합니다. 서비스 관리자를 사용해 장애 후 재시작하도록 설정합니다.
2. 전용 HTTPS 호스트의 `/visit`만 127.0.0.1:8091로 프록시합니다. 프록시가 인터넷 연결을 직접 받도록 구성하고 `X-Visit-Client-IP`를 연결 상대 IP로 덮어씁니다(Nginx: `proxy_set_header X-Visit-Client-IP $remote_addr;`). 앞단에 CDN이나 로드밸런서가 있다면 그 사업자의 신뢰된 피어에서만 클라이언트 IP를 복원하도록 검증합니다. 프록시 요청 크기를 1 KiB로 제한하고 요청량 제한을 설정합니다. 수집 API에는 공개 조회 경로가 없습니다. 브라우저 Origin 검사는 인증이 아니므로 로그 출처와 과금 여부는 네이버 자료로 확인합니다.
3. 자동추적 URL 설정 및 기존 광고 랜딩 URL 도착 시 파라미터 유지 여부를 확인합니다. 합성 방문으로 수집, 반복 표시, 만료 삭제와 폼 회귀 테스트를 마친 뒤 각 페이지 스크립트의 `data-endpoint`에 전용 HTTPS 수집 URL을 넣습니다. 홈페이지 DNS와 기존 랜딩 URL을 바꿀 필요는 없습니다.
4. 지정 관리자가 서버에서 SQLite로 필요한 기간만 조회합니다. UTC 시각은 네이버 내역과 대조할 때 KST(UTC+9)로 변환합니다. 중단 시 수집 엔드포인트를 먼저 비활성화하고 스크립트 설정을 제거합니다. 로그와 조회 결과의 폐기도 보관정책에 따릅니다.
